## 本次修复

Dreamina 重做时，共用下载目录可能残留上一次的图片；新任务还在处理中，执行器就可能返回旧图。

现在每次提交都使用独立下载目录，并在发现失败状态时拒绝交付残留文件。新增测试验证：旧图存在时仍等待新任务的结果、失败结果不会交付、错误比例不会被静默裁切。

本次未修改标题策略、模型提示词、风格配方或横竖版参考规则。

## 现有作品记录能证明什么

- 已有多个题材与两种生图路线的真实成片，可在首页与作品集查看。
- 已有任务保留了竖版选择、横版续作与最终选择，说明完整流程曾实际运行。
- 历史质量记录也保留了候选中的英文错字、标题占比不足和额外文字等问题。最终作品经过筛选或重做，不能把最终精选图当作每次首次生成的水平。

这些历史记录来自不同阶段，不作为当前 v2 的统一成功率样本。自动测试验证执行约束，也不能替代对标题、面孔、肢体和美感的读图判断。

## 稳定性结论的边界

目前可以说：**有真实作品、发布成绩和可复用流程，通过候选筛选、逐张检查与定向重做来争取高质量交付。**

若要宣称或量化“稳定生成”，仍需按 [评测协议](../EVALUATION.md) 完成五类回归，固定视频、文案、人像、比例与模型，记录全部候选、首次可用率、重做次数和最终可用率。当前仓库尚没有这份完整的 v2 统计结果。

## 复现基础检查

在仓库根目录安装依赖后运行：

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q scripts
python3 scripts/detect_dreamina_capabilities.py --requested auto
```

基础检查不调用生图模型；实际生图需要自己的模型账号、额度和可用工具。
